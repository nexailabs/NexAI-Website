# Toolkit heroes — Candidate 05 (Hybrid: Founder spine + Direct-Response hook) — REDO

**Angle:** Open the door with the reader's own next move — the tool they're about to vet, the prompt
they'd actually steal, the build log they wish existed — then earn it with evidence (it ran on real
work before we published it), never with who wrote it. No gate, no pitch; you're handing over the
thing, not selling it.

---

## App Vault

- **Eyebrow:** `App Vault · {N} tools`
- **Headline (H1):** `The stack we'd pick again.`
- **Sub:** `Every tool we run the business on — what it does, why it won, what it replaced. We pay for these. No affiliate links, no kickbacks, just the list.`

*Why (headline): the original "actually run on" defends against a strawman nobody accused us of. The question behind every tool-stack page is "would these people choose this again?" — "the stack we'd pick again" answers it as conviction. The prior version used "rebuild on tomorrow," but "tomorrow" is a faint time-word; "pick again" carries the same conviction with no clock and no contortion.*

*Why (sub): "why it won" frames each entry as a decision the tool earned against alternatives — proof, not assertion. The owned trade-off — "we pay for these, no kickbacks" — names the affiliate-funnel suspicion the skeptic is hunting for and kills it; it costs us referral revenue, which is the point.*

## Prompt Hub

- **Eyebrow:** `Prompt Hub`
- **Headline (H1):** `*[Prompts | SOPs | skills.md]* you can steal, already tested on client work.`
  *(first word rotates through: `Prompts` / `SOPs` / `skills.md` — mechanic preserved)*
- **Sub:** `Single-shot prompts, human runbooks, and skills your agent installs. Each one ran on a real account before it landed here. Some free, some paid.`

*Why (headline): "survived a month of real work" is the right wedge but leans on the clock. "Steal" is the practitioner's own verb — it's exactly what a builder does with a good prompt — and "already tested on client work" keeps the ran-in-production-before-we-published signal without a calendar number.*

*Why (sub): the proof claim ("ran on a real account before it landed here") moves into the sub so the headline stays one clean line. Dropped "via Razorpay" — the payment vendor is plumbing the buyer doesn't care about; "some free, some paid" carries everything they need to know.*

## Field Notes

- **Eyebrow:** `Field Notes`
- **Headline (H1):** `The *build logs* we wish someone had written for us.`
- **Sub:** `Essays, playbooks, and what broke — each one is something we shipped or fixed in production, written up while it was fresh. No ghostwriters, no SEO filler.`
- **Signature line:** `from the lab in Bengaluru.`

*Why (headline): "Essays, playbooks, and build logs from a company run on agents" is a table of contents, not a hook. The reader's own ache is the missing manual — the post they searched for and never found. "The build logs we wish someone had written for us" is that exact feeling, and it implies the writing comes from doing, not summarizing.*

*Why (sub) — the proof-not-author fix: the original earned trust with a credential — "written by the founders." This ICP discounts credentials; a title is not why a post is worth reading. So the sub now leads with the evidence — each post is something we **shipped or fixed in production, written up while it was fresh**. That's the real reason it's worth the read: first-hand from doing the work, not from holding a title. "what broke" stays as the owned trade-off (we publish the misses), and "no ghostwriters, no SEO filler" survives as a quality disclaimer — it rules out outsourced content — but it no longer carries the credibility; the production work does. Signature line unchanged.*

## What I'd A/B test next

1. **App Vault headline:** conviction (`the stack we'd pick again`) vs. anti-affiliate trust (`the stack we pay for, no kickbacks`) as the H1 — which earns more scroll-into-cards?
2. **Prompt Hub verb:** `you can steal` vs. a flatter `that ran on client work first` — does "steal" lift clicks from practitioners, or read as try-hard to the founder tail?
3. **Field Notes proof beat:** keeping `what broke` in the sub vs. promoting it into the headline (`The build logs — including what broke`) — test whether admitting failure up top raises or lowers time-on-page.
